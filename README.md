# Barber Telegram Bot

Лёгкий Telegram‑бот для приёма записей на услуги к Парикмахеру с хранением данных в Google Sheets, учётом таймзоны салона и автоматическими напоминаниями.

Проект написан на Node.js с использованием `telegraf` для бота и Google Sheets API для хранения расписания и записей.

**Ключевые возможности**

- Интерактивная сцена записи (услуга → дата → время → контакт → подтверждение).
- **Управление услугами**: добавление, редактирование, удаление услуг с ценами и продолжительностью (через админ-меню).
- **Управление расписанием**: настройка рабочих дней и часов мастера (как по датам, так и по дням недели) прямо через админ‑меню бота, без ручного редактирования таблицы.
- Управление слотами: учитываются блокировки из листа **«Блокировка времени»** и уже подтверждённые записи.
- Автоматическое создание листов и заголовков в Google Sheets при старте.
- Портфолио и премиальная визитка: после `/start` бот показывает 5-6 лучших работ (через `file_id` и медиагруппу), чтобы клиент сразу видел уровень мастера.
- Кнопка “Как добраться”: в главном меню клиенту отправляется ссылка на Яндекс.Карты (берётся из Google Sheets).
- Напоминания: за день записи (08:00 по таймзоне салона) и клиентам, не посещавшим салон более 21 дня (а также обычное напоминание за 2 часа до записи).
- Хранение клиентов и статистики в листе `Clients`.
- Менеджерские уведомления (опционально, через `MANAGER_CHAT_ID`).

**Требования**

- Node.js 18+ (рекомендуется).
- Аккаунт сервисного аккаунта Google с доступом редактирования к таблице.

## Быстрый старт

1. Склонируйте репозиторий и перейдите в каталог проекта.
2. Создайте файл `.env` в корне проекта со следующими переменными:

```
BOT_TOKEN=ваш_токен_бота
GOOGLE_SHEETS_ID=ID_вашей_таблицы
GOOGLE_CLIENT_EMAIL=service-account@project.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
DEFAULT_TIMEZONE=Asia/Yekaterinburg   # опционально, будет использовано по умолчанию
MANAGER_CHAT_ID=123456789            # опционально, id чата менеджера
```

Примечание: поле `GOOGLE_PRIVATE_KEY` должно содержать приватный ключ сервисного аккаунта. В `.env` символы перевода строки обычно представлены как `\n` — код автоматически заменит их на реальные символы новой строки.

3. Убедитесь, что сервисный аккаунт (его `client_email`) имеет права Editor над Google Sheet (через «Share» в Google Sheets).

4. Установите зависимости и запустите проект:

```powershell
npm install
npm start
```

На Windows `npm run dev` (если есть) может требовать установки `cross-env` для установки переменных среды; альтернативно в PowerShell можно временно выставить переменную:

```powershell
$env:NODE_ENV = "development"
node index.js
```

## Конфигурация и важные переменные

- `BOT_TOKEN` — токен вашего Telegram‑бота.
- `GOOGLE_SHEETS_ID` — ID Google Sheets таблицы, где будут храниться данные.
- `GOOGLE_CLIENT_EMAIL` — email сервисного аккаунта.
- `GOOGLE_PRIVATE_KEY` — приватный ключ сервисного аккаунта (вставляйте как одну строку с `\n`).
- `DEFAULT_TIMEZONE` — таймзона по умолчанию (используется, если в листе `Settings` нет `timezone`).
- `MANAGER_CHAT_ID` — (опционально) Telegram chat id менеджера для уведомлений.

## Интеграция с Google Calendar (новая)

В проект добавлена опциональная синхронизация записей с Google Calendar.

- Переменная окружения: `GOOGLE_CALENDAR_ID` — ID календаря, например `your-calendar-id@group.calendar.google.com` или ваш gmail-адрес при использовании личного календаря.
- Сервисный аккаунт: используйте `GOOGLE_CLIENT_EMAIL` и `GOOGLE_PRIVATE_KEY` (уже требуются для Google Sheets). Если эти переменные заданы, бот попытается создать/удалять события в календаре.

Требования и шаги настройки:

1. Включите Google Calendar API в проекте Google Cloud Console (APIs & Services → Enable APIs and Services → Google Calendar API).
2. Убедитесь, что в `.env` указаны:

```
GOOGLE_CLIENT_EMAIL=barber-bot@your-project.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_CALENDAR_ID=your-calendar-id@group.calendar.google.com
```

3. Дайте доступ сервисному аккаунту к календарю: откройте Google Calendar под аккаунтом владельца календаря (тот, чей `GOOGLE_CALENDAR_ID` вы используете), перейдите в "Настройки и доступ" нужного календаря → "Доступ к конкретным людям" → "Добавить людей" и вставьте `GOOGLE_CLIENT_EMAIL` (например `barber-bot@...iam.gserviceaccount.com`) с правом `Make changes to events`.

4. Если используете личный Gmail-календарь (`@gmail.com`), шаринг с сервисным аккаунтом также работает — сервисный аккаунт после добавления будет иметь доступ изменять события.

Если календарь не доступен или переменные окружения не заданы — интеграция игнорируется (не фатальная ошибка), бот продолжит работать с Google Sheets как раньше.

Также в `src/config/index.js` есть настройка рабочих часов `workday` (по умолчанию startHour:10, endHour:20). При необходимости можно поменять код или добавить переменные окружения.

## Структура Google Sheets

При старте бот вызывает `ensureSheetsStructure()` и создаёт (при необходимости) следующие листы со стандартными заголовками:

- `Настройки` — ключ/значение (столбцы: `ключ`, `значение`). Используется для хранения `часового_пояса`, `телефон_мастера`, `адрес_мастера`, `напоминание_28день_текст`, `ссылка_на_чаевые` (может быть ссылкой или номером телефона), `портфолио_фото` (JSON-массив `file_id`) и `ссылка_на_локацию` (ссылка на Яндекс.Карты для кнопки “Как добраться”).
- `Расписание` — столбцы: `Дата`, `День_недели`, `Время_начала`, `Время_окончания`, `Обед_начало`, `Обед_окончание`. Определяет рабочие дни и часы работы. Можно указывать конкретные даты или дни недели (понедельник, вторник и т.д.). **Важно:** Изменения в этом листе применяются мгновенно без перезагрузки бота — клиенты сразу видят актуальное расписание при выборе даты. Для производительности бот использует «окно» из первых 50 строк листа `Расписание`: устаревшие прошедшие даты автоматически вычищаются, а новые даты/шаблоны добавляются через админ‑меню.
- `Блокировка времени` — столбцы: `дата`, `время_начала`, `время_окончания`, `статус`, `услуга`, `примечание`. Для блокировок используйте `статус=заблокировано`. **Важно:** Добавление заблокированных слотов применяется мгновенно без перезагрузки бота — система сразу учитывает новые блокировки при расчёте доступных слотов.
- `Записи` — столбцы: `id`, `создано_в_utc`, `услуга`, `цена`, `дата`, `время_начала`, `время_окончания`, `имя_клиента`, `телефон`, `имя_пользователя`, `комментарий`, `статус`, `код_отмены`, `telegram_id`, `исполнено_utc`, `отменено_utc`. Колонка `цена` сохраняет стоимость услуги на момент создания записи (важно для корректной статистики доходов, так как цены могут меняться со временем). **Важно:** В этом листе хранятся только активные записи за последние 2 месяца для оптимизации производительности.
- `Записи_Архив` — столбцы идентичны листу `Записи`. Хранит исторические записи старше 2 месяцев. Автоматически создаётся при первом запуске и заполняется автоматической ротацией.
- `Клиенты` — столбцы: `id_клиента`, `впервые_увидено_в_utc`, `telegram_id`, `имя_пользователя`, `имя`, `телефон`, `последняя_запись_в_utc`, `всего_записей`, `ban_status`, `ban_reason`, `напоминание_28день_utc`, `последняя_рассылка_utc`. Поле `последняя_запись_в_utc` автоматически обновляется при завершении записи (статус "исполнено") и используется системой напоминаний за 28 дней.

**Хранение услуг:** Услуги хранятся в файле `services.json` в корне проекта. При первом запуске после обновления существующие услуги мигрируются автоматически. Управление через админ-меню («Управление услугами»).

**Мгновенное применение изменений:** Система автоматически обновляет данные из Google Sheets при каждом взаимодействии пользователя с календарём записи. Изменения в листах `Расписание` (рабочие часы) и `Блокировка времени` применяются сразу без необходимости перезагрузки бота. Это позволяет гибко управлять рабочими днями и блокировками в реальном времени.

## Как это работает (коротко)

- `index.js` инициализирует конфиг (`src/config`), Google Sheets сервис (`src/services/googleSheets.js`), запускает бота (`src/bot`) и настраивает cron‑напоминания (`src/services/reminders.js`).
- `src/bot` использует `telegraf` + `telegraf-session-local` для хранения сессий в `sessions.json` и сцен (`WizardScene`) для диалога записи (`src/bot/scenes/bookingScene.js`).
- `src/services/booking.js` отвечает за бизнес‑логику: услуги, генерацию слотов, проверку пересечений и создание записи (append в `Appointments`).
- `src/services/googleSheets.js` реализует все чтения/записи в Google Sheets и имеет простой in‑memory кэш для оптимизации чтений по датам (TTL ~30 минут для расписания дня и рабочих часов, плюс фоновая почасовая очистка устаревших записей).
- **Оптимизация производительности календаря:** При выборе даты система проверяет только рабочие часы из листа `Расписание` без проверки слотов, что значительно ускоряет загрузку календаря. Проверка доступных слотов выполняется только при клике на конкретную дату.
- **Мгновенное применение изменений:** В процессе записи система принудительно обновляет данные из Google Sheets (обходит кэш), чтобы клиенты всегда видели актуальное расписание и рабочие дни без необходимости перезагрузки бота.
- **Система архивирования для оптимизации:** Записи автоматически разделяются на активные (последние 2 месяца в листе `Записи`) и архивные (старше 2 месяцев в листе `Записи_Архив`). Клиентские операции читают только активные записи, что ускоряет работу в 3-5 раз (с 2-5 секунд до <1 секунды). История данных полностью сохраняется для админ-статистики. Автоматическая ротация выполняется ежемесячно в 3:00 ночи (1-го числа).

## Ограничение записей

Система ограничивает количество активных записей для одного пользователя:

- **Лимит:** не более 3 активных записей на любые даты
- **Проверка:** выполняется при попытке создать новую запись
- **Идентификация пользователя:** по `telegramId`, `chatId` или `phone` (проверяются все доступные идентификаторы)
- **Что происходит при превышении:** бот блокирует создание записи и сообщает пользователю о превышении лимита с предложением отменить ненужные записи

**Важно:** Ограничение учитывает все активные записи пользователя независимо от даты. Если у пользователя уже есть 3 активные записи (например, на разные дни), он не сможет создать новую запись до тех пор, пока не отменит одну из существующих.

## Бан пользователей

- Для блокировки клиента используйте админ‑функцию бота (бан по Telegram ID или username). Система синхронизирует статус между локальным файлом `banned.json` и листом `Клиенты` в Google Sheets.
- В таблице `Клиенты` статус хранится в колонках `ban_status` (значение `banned` или пусто) и `ban_reason` (опционально, причина).
- Забанированные пользователи:
  - не могут начать сцену записи — бот сообщает о блокировке и завершает сцену;
  - не могут создать запись — сервис бронирования возвращает `{ ok: false, reason: "banned" }`;
  - не получают массовые сообщения при включённом `skipBanned`.

## Команды и UX бота

- `/start` — приветствие, премиальная визитка из портфолио и базовая клавиатура (включая кнопку “Как добраться”).
- `Записаться 💇‍♂️` или `/book` — запуск сцены записи.
- `Мои записи` — показывает будущие записи пользователя с возможностью отмены (inline‑кнопки).
- `/services` — выводит список услуг и длительности.

### Админ‑режим

- Команды: `/admin` — включить режим администратора (только для менеджера с `MANAGER_CHAT_ID`), `/user` — вернуться в пользовательский режим.
- В админ‑режиме интерфейс отображается как обычная reply‑клавиатура с пунктами:
  - `Просмотр записей`, `Статистика`, `Отменить запись (по коду)`, `Массовая рассылка`, `📊 Финансовая статистика`, `📊 Статус рассылки`, `⚙️ Настройки`, `Вернуться в пользовательский режим`.
- Раздел **"⚙️ Настройки"** содержит:
  - `Забанить пользователя`, `Разбанить пользователя`, `Управление услугами`, `Редактировать напоминание 28 дней`, `Редактировать ссылку на чаевые`, `Изменить контакты`, `Назад в админ-меню`.
  - `Загрузить фото в портфолио`, `Удалить фото`, `Сохранить локацию` (доступно в том же разделе “⚙️ Настройки”).
- **Управление услугами** — добавление, редактирование, удаление и просмотр услуг с ценами и продолжительностью.
- **Редактирование ссылки на чаевые** — настройка ссылки на платёж (http://, https://, t.me/) или номера телефона, которые будут отправляться клиентам при завершении услуги. Система автоматически определяет тип данных и форматирует сообщение соответственно.
- **Финансовая статистика** — просмотр доходов по различным периодам (сегодня, вчера, неделя, месяц) с разбивкой по услугам. Учитываются только завершённые записи (статус "исполнено"). При создании записи автоматически сохраняется цена услуги на момент записи.
- Текстовые вводы админа (отмена по коду отмены, бан/разбан, текст рассылки) обрабатываются только в админ‑режиме (`ctx.session.mode === 'admin'`).
- **Массовая рассылка** с ограничениями:
  - Максимум 250 получателей в день
  - Автоматическое отслеживание отправленных клиентов через метки в таблице `Клиенты` (колонка `последняя_рассылка_utc`)
  - Клиенты, которым уже отправляли менее 24 часов назад, автоматически исключаются из рассылки
  - Если клиентов больше 250, система автоматически разбивает рассылку на несколько дней (первые 250 получат сегодня, остальные - на следующий день)
  - Метки сбрасываются автоматически каждую неделю по понедельникам в 00:00 по таймзоне салона
  - Предпросмотр показывает количество доступных получателей, ожидающих рассылку и статус ограничений
  - Кнопка "📊 Статус рассылки" показывает подробную информацию о текущем состоянии рассылки

Процесс записи: выбор услуги → выбор даты (инлайн‑кнопки) → выбор времени (слоты по 15 минут, с шагом) → ввод имени и отправка контакта → комментарий → подтверждение.

Поведение календаря выбора даты:

- Показаны только даты текущего месяца. После 15-го числа текущего месяца дополнительно открывается возможность записи на следующий месяц.
- Прошедшие дни не отображаются (учитывается таймзона салона).
- **Отображаются только рабочие дни:** В календаре показываются только те даты, для которых в листе `Расписание` указаны рабочие часы. Выходные дни (без записей в листе `Расписание`) автоматически скрываются из календаря.
- **Быстрая загрузка:** Календарь загружается быстро, так как проверяет только наличие рабочих часов, а не доступность слотов. Проверка свободных слотов выполняется только при клике на конкретную дату.
- **Актуальность данных:** При каждом открытии календаря и переключении месяцев система обновляет данные из листа `Расписание`, поэтому изменения в расписании применяются мгновенно без перезагрузки бота.

## Напоминания и cron

- В 08:00 (по таймзоне салона) бот отправляет напоминания клиентам о записях на завтра.
- Каждые 5 минут проверяется окно «~2 часа до записи» и отправляются одноразовые напоминания клиентам (есть in‑memory кэш `twoHourRemindedIds`, чтобы не слать повторно).
- Каждые 30 минут автоматически завершаются прошедшие записи: статус меняется на "исполнено" сразу после окончания времени услуги.
- **Напоминание для неактивных клиентов**: ежедневно в 11:00 бот проверяет клиентов, которые не посещали салон более 28 дней и не имеют активных записей, и отправляет им дружелюбное напоминание с предложением записаться. Напоминание отправляется только один раз, о чём свидетельствует заполненное поле `напоминание_28день_utc` в таблице клиентов. При создании новой записи это поле очищается, чтобы клиент снова мог получить напоминание через 28 дней. **Оптимизация:** Система использует оптимизированный алгоритм (O(n) вместо O(n\*m)), который проверяет поле `последняя_запись_в_utc` из таблицы клиентов как основной источник данных, без перебора всех записей. Поле `последняя_запись_в_utc` автоматически обновляется при завершении записи (статус "исполнено").
- Каждый день в 00:00 UTC очищается кэш `twoHourRemindedIds` (сброс защиты от повторных 2‑часовых напоминаний на следующие даты).
- Каждую неделю по понедельникам в 00:00 (по таймзоне салона) автоматически сбрасываются метки массовой рассылки (`последняя_рассылка_utc` в таблице `Клиенты`), что позволяет запустить новый цикл рассылки для всех клиентов.
- Каждый час выполняется лёгкая очистка in‑memory кэша Google Sheets (расписание и рабочие часы): удаляются только устаревшие записи, актуальные данные остаются в памяти.
- Ночью в 02:00 (по таймзоне салона) запускается очистка `sessions.json`: удаляются только сессии, которые не проявляли активности более 30 дней, и при этом общее число сессий ограничивается последними 150 по активности. Активные и недавно использовавшие бота пользователи, а также текущие незавершённые записи не затрагиваются.
- **Ежемесячная ротация записей в архив:** 1-го числа каждого месяца в 3:00 ночи автоматически переносятся записи старше 2 месяцев из листа `Записи` в лист `Записи_Архив` для поддержания оптимальной производительности.
- Между отправками сообщений в напоминаниях используется троттлинг ~500 мс, а сами cron‑задачи защищены от параллельного выполнения (повторный запуск пропускается, если предыдущий ещё идёт).

## Надёжность и обработка ошибок

Бот включает комплексную систему обработки ошибок для предотвращения краха процесса при ошибках Telegram API.

### Глобальные обработчики ошибок

- **unhandledRejection** — перехватывает необработанные отклонённые промиссы
- **uncaughtException** — перехватывает необработанные исключения
- Ошибки Telegram API (403, 429, 400) обрабатываются без завершения процесса
- Критические ошибки логируются и завершают процесс с кодом 1

### Безопасная отправка сообщений

Все критические отправки сообщений используют утилиту `safeMessaging.js`:

- **safeSendMessage** — безопасная отправка текстовых сообщений
- **safeSendPhoto** — безопасная отправка фото
- **safeReply** — безопасный ответ через ctx.reply

**Обрабатываемые ошибки:**

- **403 Forbidden** — пользователь заблокировал бота (логируется как предупреждение, не критично)
- **400 Bad Request** — неверный запрос (логируется как предупреждение)
- **429 Too Many Requests** — превышен лимит запросов (логируется с информацией о времени повтора)
- Другие ошибки логируются с деталями

**Где используется:**

- Все напоминания (`src/services/reminders.js`)
- Массовые рассылки (`src/services/admin.js`)
- Уведомления менеджеру (`src/bot/index.js`, `src/bot/scenes/bookingScene.js`)
- Уведомления пользователям об отмене записей

Это гарантирует, что бот продолжит работать даже если некоторые пользователи заблокировали бота или произошли временные ошибки Telegram API.

## Безопасность

Бот включает комплексные меры безопасности для защиты от неавторизованного доступа, DDoS-атак, инъекций и утечек данных.

### Реализованные меры безопасности

1. **Проверка доступа администратора**
   - Все админ-команды доступны только пользователю с `MANAGER_CHAT_ID`
   - Функция `isAdmin()` проверяет права доступа во всех 26 админ-обработчиках
   - Проверка выполняется перед каждой критичной операцией

2. **Rate Limiting (ограничение частоты запросов)**
   - Middleware ограничивает частоту запросов для защиты от DDoS и спама
   - Лимиты: общие команды (30/минуту), админ-команды (10/минуту), сцены (5/минуту)
   - Оптимизация памяти: автоматическая очистка неактивных пользователей (>10 минут), LRU eviction при превышении 5000 записей

3. **Валидация входных данных**
   - Валидация Telegram ID, ID записей, телефонных номеров
   - Валидация имен и комментариев с ограничением длины
   - LRU кэш результатов валидации (100 записей) для оптимизации производительности
   - Ранний выход при простых проверках (длина перед regex)

4. **Защита от XSS (Cross-Site Scripting)**
   - Санитизация всех текстовых полей (экранирование HTML-спецсимволов)
   - Ограничение длины вводимых данных
   - Защита текста рассылок и комментариев

5. **Защита сессий**

- Проверка размера сессий (максимум 10KB на пользователя)
- Предотвращение DoS через большие сессии
- Валидация структуры сессии при загрузке
- Периодическая очистка `sessions.json`: удаление сессий с отсутствием активности более 30 дней и ограничение общего числа записей (хранится не более 150 самых свежих активных сессий; текущие активные пользователи и незавершённые записи не удаляются)

6. **Логирование критичных действий**
   - Структурированное логирование критичных операций (CRITICAL и ERROR) в `logs/security.log`
   - Асинхронная буферизация (batch writes каждые 2 секунды или при 50 записях)
   - Логи сохраняются в `logs/security.log` с ротацией по размеру (максимум 10MB)

7. **Ограничение массовых операций**
   - Максимальное количество получателей рассылки: 250 в день
   - Автоматическое отслеживание отправленных клиентов через метки (`последняя_рассылка_utc`)
   - Клиенты, которым отправляли менее 24 часов назад, автоматически исключаются
   - Автоматический сброс меток каждую неделю по понедельникам в 00:00
   - Между сообщениями в рассылке используется троттлинг (по умолчанию ~750 мс)
   - Подтверждение требуется для всех рассылок
   - Логирование всех массовых рассылок с количеством получателей

8. **Проверка зависимостей**
   - Скрипты для аудита безопасности: `npm run audit`, `npm run audit:fix`, `npm run security-check`
   - Рекомендуется регулярно запускать `npm run security-check` для проверки уязвимостей

### Файлы безопасности

- `src/utils/security.js` - утилиты валидации и санитизации
- `src/middleware/rateLimiter.js` - rate limiting middleware
- `src/utils/logger.js` - структурированное логирование
- `src/utils/backup.js` - резервное копирование

### Заметки по развёртыванию

- Не коммитите `.env`, `credentials.json`, `sessions.json`, `banned.json` или `logs/` в публичные репозитории
- Для продакшена используйте process manager (pm2, systemd) и перенаправление логов
- Регулярно проверяйте логи безопасности в `logs/security.log`
- Периодически запускайте `npm run security-check` для проверки уязвимостей зависимостей
