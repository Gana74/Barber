# Инструкция для менеджера

Этот файл — краткая инструкция для менеджера салона по работе с ботом и таблицей Google Sheets.

## Кому полезно

- Менеджеру, который хочет просматривать записи, блокировать время и получать уведомления о новых/отменённых записях.

## Привязка к Google Таблицам и Google Календарю + скачивание credentials.json

Ниже описана настройка доступа бота к Google Sheets и Google Calendar через сервисный аккаунт Google. В результате вы получите файл credentials.json (для хранения локально) и заполните переменные в .env.

Важное:

- В рантайме проект использует переменные окружения GOOGLE_CLIENT_EMAIL и GOOGLE_PRIVATE_KEY, а не файл credentials.json напрямую. JSON можно хранить локально как источник данных для этих переменных.
- Никогда не коммитьте credentials.json и .env в публичный репозиторий.

Шаг 1 — Создайте проект в Google Cloud Console

1. Откройте https://console.cloud.google.com (войдите под вашим Google‑аккаунтом).
2. В верхней панели нажмите Select project → New Project, задайте имя (например, Barber Bot) и создайте проект.

Шаг 2 — Включите API

1. Откройте меню APIs & Services → Library.
2. Найдите и включите:
   - Google Sheets API
   - Google Calendar API

Шаг 3 — Создайте сервисный аккаунт

1. Перейдите в IAM & Admin → Service Accounts → Create Service Account.
2. Задайте имя (например, barber-bot) и создайте.
3. Роль на шаге Assign roles можно пропустить либо выбрать Editor (необязательно для доступа к конкретным ресурсам, т.к. доступ будет дан через «Поделиться» в Sheets/Calendar).
4. После создания откройте созданный аккаунт → Keys → Add key → Create new key → JSON. Скачается файл credentials.json.

Что важно из credentials.json:

- client_email — адрес сервисного аккаунта вида something@project-id.iam.gserviceaccount.com
- private_key — приватный ключ (многострочный блок между BEGIN/END PRIVATE KEY)

Шаг 4 — Поделитесь доступом к Google Sheet с сервисным аккаунтом

1. Откройте вашу таблицу Google Sheets, где будут храниться данные.
2. Нажмите Share и добавьте client_email из credentials.json как Editor (Редактор).
3. Сохраните.

Как получить ID таблицы (GOOGLE_SHEETS_ID):

- Откройте таблицу в браузере. В URL часть между /d/ и /edit — это ID.
  Пример: https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpqR/edit → ID = 1AbCdEfGhIjKlMnOpqR

Шаг 5 — Дайте сервисному аккаунту доступ к календарю

1. Откройте Google Calendar (в браузере) под владельцем нужного календаря.
2. Слева выберите нужный календарь → «Настройки и доступ» → «Открыть доступ для конкретных пользователей» → «Добавить пользователей».
3. Впишите client_email и назначьте право «Вносить изменения в события» (Make changes to events).

Как получить ID календаря (GOOGLE_CALENDAR_ID):

- Для вторичных календарей ID отображается в настройках календаря (раздел «Интегрировать календарь»), обычно вида your-calendar-id@group.calendar.google.com.
- Для основного календаря аккаунта Google можно использовать email владельца (например, your.name@gmail.com).

Шаг 6 — Заполните .env в корне проекта
Создайте/откройте файл .env и заполните значения:

BOT*TOKEN=ваш*токен*бота
GOOGLE_SHEETS_ID=скопированный_id*таблицы
GOOGLE*CLIENT_EMAIL=client_email*из*credentials.json
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_CALENDAR_ID=идентификатор*календаря # опционально, для синхронизации с календарём
DEFAULT_TIMEZONE=Asia/Yekaterinburg # опционально
MANAGER_CHAT_ID=123456789 # опционально, уведомления менеджера

Подсказки по GOOGLE_PRIVATE_KEY:

- Ключ многострочный. В .env его нужно записать одной строкой, заменив переводы строк на символы \n.
- Код автоматически преобразует \n в реальные переводы строк при запуске.

Шаг 7 — Проверка работы

1. Установите зависимости и запустите бота:
   npm install
   npm start
2. На первом запуске сервис создаст недостающие листы и заголовки в таблице. Если прав недостаточно, в логах будет ошибка «insufficient permissions» — проверьте, что вы расшарили таблицу сервисному аккаунту как Editor.
3. Для календаря: при создании новых записей должны появляться события в указанном календаре. Если нет — проверьте GOOGLE_CALENDAR_ID и доступ «Вносить изменения в события» для client_email.

Устранение неполадок

- PERMISSION_DENIED при обращении к таблице/календарю: проверьте, что именно client_email из credentials.json добавлен в доступы и роль — Editor (таблица) / Make changes to events (календарь).
- invalid_grant/unauthorized_client: убедитесь, что включены нужные API в Google Cloud (Sheets/Calendar) и что время на сервере синхронизировано (NTP).
- malformed private key: проверьте кавычки и экранирование \n в GOOGLE_PRIVATE_KEY в .env.
- События не создаются, но записи в таблице есть: проверьте наличие GOOGLE_CALENDAR_ID. Без него календарная интеграция отключена, это не ошибка.

Примечание о credentials.json

- Файл можно хранить только локально для справки. В репозиторий не добавлять. Для продакшена используйте исключительно переменные окружения.

## Включение менеджерских уведомлений

1. В `.env` (или в переменных окружения на сервере) задайте `MANAGER_CHAT_ID` равным вашему Telegram chat id.
2. Если `MANAGER_CHAT_ID` не задан, уведомления менеджера не отправляются.

Как получить свой Chat ID (простые варианты):

- В Telegram найдите бота `@userinfobot` или `@getidsbot`, нажмите Start — бот покажет ваш id.
- Либо попросите разработчика временно включить логирование `ctx.from.id` при вашем сообщении в бота.

После установки `MANAGER_CHAT_ID` и перезапуска бота вы будете получать уведомления о новых записи и об отменах.

## Просмотр записей

- В боте: используйте кнопку `Просмотр записей` в админ-меню. Бот покажет активные записи с кодами отмены (первые 50 записей).
- В Google Sheets: откройте таблицу, указанную в `GOOGLE_SHEETS_ID`.
- Лист `Записи` содержит активные записи за последние 2 месяца. Отфильтруйте по столбцу `Статус` = `активна` и дате.
- Лист `Записи_Архив` содержит исторические записи старше 2 месяцев (для полной истории используйте оба листа).
- Полезные столбцы: `ID_записи`, `Услуга`, `Цена`, `Дата`, `Время_начала`, `Время_окончания`, `Имя_клиента`, `Телефон`, `Username_Telegram`, `Комментарий`, `Код_отмены`.

**Оптимизация производительности:**
- Система автоматически разделяет записи на активные (последние 2 месяца) и архивные (старше 2 месяцев)
- Это обеспечивает быструю работу бота при выборе времени клиентами (<1 секунда вместо 2-5 секунд)
- Для админ-статистики и отчётов система автоматически объединяет данные из обоих листов

## Бан пользователей

- Для бана используйте функцию в разделе **«⚙️ Настройки»** → **«Забанить пользователя»**. В таблице на листе `Клиенты` будет установлен `BanStatus = banned`, а в `BanReason` — причина (если указали).
- Разбан: функция **«⚙️ Настройки»** → **«Разбанить пользователя»** снимет бан в таблице (`BanStatus` очистится) и из локального списка `banned.json`.
- Забанированные пользователи:
  - не могут начать сцену записи (бот сообщит о блокировке и завершит сцену);
  - не могут создать запись (сервис бронирования вернёт ошибку `reason: banned`);
  - исключаются из рассылок при включённой опции `skipBanned`.

## Работа в боте — админ‑режим

- Откройте диалог с ботом и выполните команду `/admin`. Команда активна только для аккаунта, чей `id` совпадает с `MANAGER_CHAT_ID`.
- В админ‑режиме бот показывает reply‑клавиатуру с пунктами:
  - `Просмотр записей` — показать активные записи (первые 50 строк) с кодами отмены;
  - `Статистика` — краткая статистика: количество активных записей и число клиентов в базе;
  - `Отменить запись (по коду)` — введите код отмены записи для отмены (после ввода бот подтвердит и, при наличии `telegram_id` клиента, уведомит его);
  - `Массовая рассылка` — введите текст рассылки, получите предпросмотр (количество получателей и примеры), затем подтвердите или отмените отправку. Ограничение: максимум 250 получателей в день. Клиенты, которым уже отправляли менее 24 часов назад, автоматически исключаются. Если клиентов больше 250, рассылка автоматически разобьётся на несколько дней;
  - `📊 Финансовая статистика` — просмотр доходов по различным периодам с разбивкой по услугам;
  - `📊 Статус рассылки` — показывает текущий статус массовой рассылки: количество клиентов, которым можно отправить сегодня, общее количество клиентов, ожидающих рассылку, и дату следующего сброса меток;
  - `⚙️ Настройки` — открывает раздел настроек с дополнительными функциями;
  - `Вернуться в пользовательский режим` — переключиться обратно на обычную клавиатуру клиента.

**Раздел "⚙️ Настройки"** содержит:

- `Забанить пользователя` — введите Telegram ID или `@username`; если найден по username, будет использован `telegram_id` из таблицы `Clients`;
- `Разбанить пользователя` — введите Telegram ID для снятия блокировки;
- `Управление услугами` — добавление, редактирование, удаление и просмотр услуг;
- `Редактировать напоминание 21 день` — редактирование текста напоминания для неактивных клиентов;
- `Редактировать ссылку на чаевые` — настройка ссылки на чаевые, отправляемой клиентам при завершении услуги;
- `Изменить контакты` — изменение телефона и адреса салона, которые отправляются клиентам в напоминаниях;
- `Загрузить фото в портфолио` — загрузите фото работ мастера; бот сохранит `file_id` в лист `Настройки` (ключ `портфолио_фото`) и обновит премиальную визитку в `/start`;
- `Удалить фото` — удалите одно из фото портфолио: бот покажет нумерованный список, а вы выберете номер для удаления (обновляется ключ `портфолио_фото`);
- `Сохранить локацию` — отправьте ссылку на Яндекс.Карты для схемы проезда (перезаписывается в `Настройки` ключ `ссылка_на_локацию`);
- `Настройки расписания` — управление рабочими днями и часами прямо через бота (см. ниже);
- `Назад в админ-меню` — возврат в главное админ-меню.

### Портфолио и премиальная визитка

После команды клиента `/start` бот показывает 5-6 лучших работ из портфолио (источник: `Настройки.портфолио_фото`).

Как обновить:

- `⚙️ Настройки` → `Загрузить фото в портфолио` — отправьте фото (сохраняется `file_id`).
- `⚙️ Настройки` → `Удалить фото` — удалите фото по номеру в списке.

### Как добраться (карта)

Кнопка “Как добраться” доступна в главном меню клиента и открывает ссылку Яндекс.Карт (источник: `Настройки.ссылка_на_локацию`).

Как обновить:

- `⚙️ Настройки` → `Сохранить локацию` — перезапишите ссылку в таблице.

Примечание: все текстовые операции (ввод кода отмены, текста рассылки и т.п.) ожидают ввода после выбора соответствующего пункта клавиатуры; отмена текущего админ‑действия — команда `/admin_cancel`.

### Управление расписанием через бота

Менеджер может управлять рабочими днями и часами мастера не только через Google Sheets, но и напрямую в боте.

**Как открыть:**

1. `/admin` → включить админ‑режим.
2. Нажать **"⚙️ Настройки"**.
3. Нажать **"Настройки расписания"**.

Откроется подменю:

```
[Просмотр расписания на дату]
[Изменить/добавить расписание на дату]
[Удалить расписание на дату]
[Посмотреть всё расписание]
[Шаблоны по дням недели]
[Назад в админ-меню]
```

Кратко по функциям:

- **Просмотр расписания на дату** — введите дату (`ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`), бот покажет рабочее время и обед (если заданы) или сообщит, что это выходной.
- **Изменить/добавить расписание на дату** — пошаговый диалог:
  - дата → начало рабочего дня → конец рабочего дня → обед (время или `-` для отсутствия) → подтверждение.
  - данные сохраняются в лист `Расписание`, изменения сразу видны клиентам в календаре.
- **Удалить расписание на дату** — после ввода даты бот удаляет расписание для неё, день становится выходным.
- **Посмотреть всё расписание** — бот выводит текущее окно расписания (первые 50 строк листа `Расписание`): отдельные даты + шаблоны по дням недели.
- **Шаблоны по дням недели** — просмотр и редактирование стандартных часов работы по дням недели:
  - можно создать/обновить шаблон (`Пн`, `Вт`, `mon` и т.п.) с одним диалогом (начало/конец/обед),
  - можно удалить шаблон командой вида `удалить Пн`.

> Внутри кода используется «скользящее окно» из 50 строк листа `Расписание`: устаревшие прошедшие даты автоматически очищаются, чтобы таблица не разрасталась, а актуальное расписание оставалось компактным.

## Финансовая статистика

Функция позволяет отслеживать доходы мастера по различным периодам и анализировать эффективность услуг.

### Как использовать

1. В админ‑режиме нажмите кнопку **"📊 Финансовая статистика"**
2. Бот покажет inline‑кнопки с доступными периодами:
   - **Сегодня** — доходы за текущий день
   - **Вчера** — доходы за вчерашний день
   - **Эта неделя** — доходы с понедельника текущей недели по сегодня
   - **Прошлая неделя** — доходы за прошлую неделю (понедельник — воскресенье)
   - **Этот месяц** — доходы с 1‑го числа текущего месяца по сегодня
   - **Прошлый месяц** — доходы за весь прошлый месяц
   - **По услугам** — статистика по всем услугам за всё время (без фильтра по дате)
3. Выберите нужный период, нажав на соответствующую кнопку
4. Бот покажет статистику доходов

### Что показывает статистика

**Пример вывода:**

```
📈 Выручка за 10 января 2026:
• Всего: 12 500 ₽
• Средний чек: 1 562,5 ₽
• Записей исполнено: 8
• Новых клиентов: 3
• Записей отменено: 2

Топ услуг:
• Мужская стрижка — 6 000 ₽ (4 записи)
• Оформление бороды — 4 500 ₽ (3 записи)
• Женская стрижка — 2 000 ₽ (1 запись)
```

**Информация в статистике:**

- **Всего** — общая сумма доходов за выбранный период
- **Средний чек** — средняя сумма с завершённой записи за выбранный период
- **Записей исполнено** — количество завершённых записей (статус "исполнено")
- **Новых клиентов** — сколько клиентов впервые посетили салон в выбранный период (по полю `Первое_посещение_UTC` в листе `Клиенты`)
- **Записей отменено** — количество записей, отменённых в выбранный период (по полю `Отменено_UTC`)
- **Топ услуг** — список услуг, отсортированный по сумме доходов (от большей к меньшей)
  - Для каждой услуги показывается: название, сумма доходов, количество записей

### Важные особенности

- **Учитываются только завершённые записи** — статистика включает только записи со статусом "исполнено"
- **Цена сохраняется при создании записи** — при создании записи автоматически сохраняется цена услуги на момент записи. Это важно, так как цены могут меняться со временем, а статистика должна отражать реальную стоимость на момент оказания услуги
- **Фильтрация по дате исполнения** — для периодов используется дата из поля `Исполнено_UTC` (приоритет) или дата записи (если `Исполнено_UTC` пусто)
- **Услуги без цены** — записи с пустой или нулевой ценой не учитываются в расчёте доходов, но учитываются в количестве записей

### Периоды

- **Сегодня/Вчера** — от начала до конца дня по таймзоне салона
- **Неделя** — с понедельника по воскресенье (или по сегодня для текущей недели)
- **Месяц** — с 1‑го числа по последний день месяца (или по сегодня для текущего месяца)
- **По услугам** — все завершённые записи без ограничения по дате

### Структура данных в Google Sheets

В листе `Записи` добавлена колонка **`Цена`** (после колонки `Услуга`), которая автоматически заполняется при создании записи. Для старых записей, созданных до добавления этой функции, колонка может быть пустой — такие записи не учитываются в расчёте доходов.

# Руководство менеджера: массовая рассылка (текст и картинки)

## Возможности рассылки

- Текстовая рассылка (обычные сообщения).
- Рассылка изображения (одно фото) с подписью.
- Фильтрация получателей по бан-листу (забаненные не получают сообщения).
- Автоматическое отслеживание отправленных клиентов через метки (исключаются те, кому уже отправляли менее 24 часов назад).
- Предпросмотр перед отправкой и явное подтверждение с информацией о статусе рассылки.
- Автоматическое разбиение рассылки на несколько дней при количестве клиентов более 250.
- Троттлинг отправок (по умолчанию 750 мс между сообщениями), чтобы снизить риск ограничения со стороны Telegram.

## Как отправить текстовую рассылку

1. Перейдите в режим администратора командой /admin.
2. Нажмите кнопку «Массовая рассылка».
3. Отправьте текст рассылки одним сообщением.

5. Нажмите «Подтвердить рассылку ✅» для старта или «Отменить ❌» для отмены.

После завершения бот вернёт статистику: сколько отправлено успешно и сколько с ошибками.

## Как отправить рассылку с картинкой

1. Перейдите в режим администратора командой /admin.
2. Нажмите кнопку «Массовая рассылка».
3. Отправьте фото как сообщение с вложением. Можно добавить подпись к фото (это будет caption).
4. Бот посчитает количество получателей, покажет предпросмотр (отдельно отправит фото и подпись), предложит подтвердить или отменить.

Важно:

- Берётся последнее (самое большое) превью из массива фотографий, предоставляемого Telegram (file_id), и оно же используется для отправки.
- Отправляется одно фото на сообщение (альбомы/несколько фото одним месседжем не поддерживаются).

## Ограничения и примечания

- **Максимум 250 получателей в день** — система автоматически ограничивает количество получателей.
- Получатели формируются из базы клиентов (sheetsService.getClientsForBroadcast), у которых есть telegramId, за вычетом бан-листа и тех, кому уже отправляли менее 24 часов назад.
- Клиенты автоматически отмечаются меткой времени рассылки (`последняя_рассылка_utc` в таблице `Клиенты`).
- Если клиентов больше 250, система автоматически разбивает рассылку на несколько дней:
  - Первые 250 получат рассылку сегодня
  - Остальные автоматически получат рассылку на следующий день (когда метки станут старше 24 часов)
- Метки рассылки автоматически сбрасываются каждую неделю по понедельникам в 00:00 по таймзоне салона.
- Бан/разбан доступен в разделе **«⚙️ Настройки»** и влияет на рассылку.
- При большом списке рассылка может занять время из-за троттлинга (750 мс между сообщениями). Это значение можно менять в коде при вызове adminService.broadcastToClients.
- Для фото используется sendPhoto(fileId, { caption }). Для текста — sendMessage(text).
- Кнопка **"📊 Статус рассылки"** в админ-меню показывает текущий статус массовой рассылки: количество клиентов, которым можно отправить сегодня, общее количество клиентов, ожидающих рассылку, и дату следующего сброса меток.

## Безопасность и ограничения

### Ограничения массовых рассылок

- Максимальное количество получателей: **250 в день**
- Система автоматически отслеживает отправленных клиентов через метки в таблице `Клиенты` (колонка `последняя_рассылка_utc`)
- Клиенты, которым уже отправляли менее 24 часов назад, автоматически исключаются из рассылки
- Если доступно более 250 клиентов, система автоматически разбивает рассылку на несколько дней
- Метки рассылки сбрасываются автоматически каждую неделю по понедельникам в 00:00 по таймзоне салона
- Между сообщениями в рассылке используется троттлинг ~750 мс (по умолчанию)
- Все рассылки требуют подтверждения перед отправкой
- Все массовые рассылки логируются в `logs/security.log`

### Rate Limiting

Бот защищён от злоупотребления через ограничение частоты запросов:

- Админ-команды: максимум 10 запросов в минуту
- При превышении лимита пользователь получит сообщение "Слишком много запросов. Пожалуйста, подождите немного."

### Резервное копирование

- Автоматические бэкапы создаются раз в день
- Дополнительные бэкапы создаются при критичных операциях (бан/разбан пользователя, массовая рассылка)
- Бэкапы хранятся в директории `backups/` и автоматически удаляются через 30 дней
- Бэкапируются файлы: `sessions.json`, `banned.json`, `services.json`

### Логирование

Все критичные действия администратора логируются:

- Включение/выключение админ-режима
- Бан/разбан пользователей
- Отмена записей администратором
- Массовые рассылки
- Управление услугами
- Редактирование напоминания 21 день
- Редактирование ссылки на чаевые
- Изменение контактов салона

Логи доступны в файле `logs/security.log` и помогают отслеживать все административные действия.

- «Отменить ❌» или /admin_cancel — отмена текущего действия администратора.

## Отмена записи вручную

**Через бота (рекомендуется):**

1. Используйте кнопку `Просмотр записей` в админ-меню, чтобы найти нужную запись и её код отмены.
2. Нажмите `Отменить запись (по коду)` и введите код отмены (например: `A3K9X2`).
3. Бот отменит запись и уведомит клиента (если у клиента есть Telegram).

**Через Google Sheets:**

1. В `Записи` найдите строку с нужной записью.
2. В колонке `Статус` установите `отменена`.
3. В колонке `Отменено_UTC` впишите текущее время в формате ISO (например: `2025-12-23T10:30:00Z`).
4. (Опционально) отправьте клиенту сообщение вручную, если нужно; бот отправит уведомление, только если отмену сделает клиент через интерфейс.

> Примечание: корректная отмена нужна, чтобы система не предлагала занятые слоты и чтобы отчёты были точными. Код отмены можно найти в колонке `Код_отмены` в таблице или в сообщении менеджеру при создании записи.

## Статусы записей

- `активна` — запись активна, клиент ожидает услугу
- `отменена` — запись отменена клиентом или администратором
- `исполнено` — услуга оказана, запись автоматически завершена
- `заблокировано` — время заблокировано для записи

## Автоматическое завершение записей

Система автоматически обновляет статус записей на "исполнено" сразу после окончания времени услуги. Проверка происходит каждые 30 минут.

## Автоматическая ротация записей в архив

**Когда:** 1-го числа каждого месяца в 3:00 ночи по таймзоне салона

**Что происходит:** Записи старше 2 месяцев автоматически переносятся из листа "Записи" в лист "Записи_Архив"

**Зачем это нужно:**
- Поддержание высокой скорости работы бота при выборе времени клиентами (<1 секунда вместо 2-5 секунд)
- Оптимизация использования памяти (5-10MB вместо 20-30MB)
- Сохранение всей истории данных для статистики и отчётов

**Важно:**
- Ротация выполняется автоматически, ничего делать не нужно
- История данных полностью сохраняется в архиве
- Админ-статистика и отчёты работают с данными из обоих листов (активные + архив)
- При первом запуске после обновления старые записи автоматически мигрируют в архив

**Новая колонка в листе "Записи":**

- `Исполнено_UTC` — дата и время отметки об исполнении (формат ISO UTC)

**Уведомление клиенту:**

После автоматического завершения записи клиент получает уведомление с благодарностью и ссылкой на чаевые (если ссылка настроена через админ-меню). Формат сообщения: "{название услуги} завершена, благодарю что выбираете меня! В благодарность мастеру можете дать чаевые {ссылка}".

Ссылку на чаевые можно настроить через раздел **«⚙️ Настройки»** → **«Редактировать ссылку на чаевые»**. Ссылка должна начинаться с `http://`, `https://` или `t.me/`.

## Блокировка слотов (закрыть время для записи)

Блокировка производится через лист `Блокировка времени`. Ниже — подробные правила формата и примеры.

**Формат строки (колонки в таблице):** `Дата | Время_начала | Время_окончания | Статус | Услуга | Примечание`

- `Дата` — дата в формате `YYYY-MM-DD` (пример: `2025-12-24`).
- `Время_начала` / `Время_окончания` — время в 24‑часовом формате `HH:MM` (пример: `13:00`, `09:30`). Часы и минуты должны быть с ведущими нулями.
- `Статус` — значение `заблокировано` (строго). Только строки со `Статус = заблокировано` учитываются как блокировка.
- `Услуга` — опционально; можно оставить пустым или указать причину/услугу (например, `ВСЕ` или `ВЫХОД`).
- `Примечание` — короткое пояснение для менеджеров (например, `перерыв`, `праздник`, `ремонт`).

**Практические примеры** (вставлять начиная со строки 2, под заголовком):

- Блокировка обеда 24 декабря с 13:00 до 14:00:
  - `2025-12-24 | 13:00 | 14:00 | заблокировано | | перерыв на обед`
- Блокировка всего дня (закрыть запись на весь день):
  - `2025-12-31 | 00:00 | 23:59 | заблокировано | | закрыто на Новый год`

**Как отменить блокировку:**

- Удалите соответствующую строку из `Блокировка времени` или измените `Статус` на любое значение, отличное от `заблокировано` (например, оставьте пустым или `открыто`). После этого слот снова будет считаться доступным.

**Важные нюансы:**

- Времена и даты интерпретируются в таймзоне салона (см. `Настройки.таймзона` или `DEFAULT_TIMEZONE` в `.env`). Убедитесь, что задаёте время в правильной таймзоне.
- **Изменения применяются мгновенно** — система автоматически обновляет данные из листа `Блокировка времени` при каждом расчёте доступных слотов, поэтому новые блокировки учитываются сразу без перезагрузки бота.
- Для блокировки нескольких промежутков подряд добавляйте отдельные строки для каждого интервала.
- Не используйте пересекающиеся блокировки с существующими записями без предварительной договорённости с клиентами — это не отменяет уже подтверждённые записи автоматически.

Если нужна помощь — напишите разработчику, и он подскажет формат или внесёт массовые блокировки.

## Рабочие часы (лист `Расписание`)

Лист `Расписание` позволяет задать часы работы по дням недели и/или отдельные исключения по конкретным датам. Этот лист определяет, какие дни отображаются в календаре записи для клиентов.

**Колонки (заголовок должен быть в первой строке):**

- `Дата` — опционально, конкретная дата в формате `YYYY-MM-DD`. Если заполнено, имеет приоритет над `День_недели`.
- `День_недели` — опционально, день недели (например: `понедельник`, `вторник`, `пн`, `вт`, `mon`, `tue` и т.п.). Используется, когда `Дата` не заполнена.
- `Время_начала` — в формате `HH:MM` (например, `09:00`).
- `Время_окончания` — в формате `HH:MM` (например, `18:00`).
- `Обед_начало` — опционально, начало обеда в формате `HH:MM` (например, `13:00`).
- `Обед_окончание` — опционально, конец обеда в формате `HH:MM` (например, `14:00`).

**Правило приоритетов:**

- Если для конкретной `Дата` задана запись — она имеет приоритет и применяется в первую очередь.
- Если для даты нет записи, используется строка по `День_недели`.
- Если нет ни той, ни другой записи — день считается выходным и **не отображается в календаре записи**.

**Примеры (вставлять со строки 2):**

- Рабочие часы по понедельникам: ` | понедельник | 10:00 | 20:00`
- Рабочие часы по понедельникам (короткая форма): ` | пн | 10:00 | 20:00`
- Специальные часы на 2025-05-01: `2025-05-01 |  | 12:00 | 16:00`
- Рабочие часы по понедельникам с обедом: ` | пн | 10:00 | 20:00 | 13:00 | 14:00`
- Специальные часы на 2025-05-01 с обедом: `2025-05-01 |  | 12:00 | 16:00 | 13:00 | 14:00`

**Важные особенности:**

- **Изменения применяются мгновенно** — при каждом открытии календаря система автоматически обновляет данные из листа `Расписание`, поэтому изменения в расписании видны клиентам сразу без перезагрузки бота.
- **В календаре показываются только рабочие дни** — дни без записей в листе `Расписание` автоматически скрываются из календаря записи.
- **Быстрая загрузка календаря** — система проверяет только наличие рабочих часов, а не доступность слотов, что значительно ускоряет загрузку календаря.
- Формат времени должен быть корректным `HH:MM`. Некорректные строки будут игнорироваться, и день может считаться выходным.
- Если для дня указаны рабочие часы, но все слоты заняты или заблокированы, дата всё равно будет видна в календаре (при клике клиент увидит сообщение об отсутствии свободных слотов).

## Если уведомления не приходят

- Проверьте, что в `.env` задан `MANAGER_CHAT_ID`.
- Убедитесь, что бот запущен (`node index.js` или через process manager) и что бот не заблокирован вашим аккаунтом.
- Проверьте логи бота на предмет ошибок (доступ к логам есть у разработчика/администратора сервера).

## Управление услугами

Администратор может управлять услугами через раздел **«⚙️ Настройки»** → **«Управление услугами»** в админ-меню.

### Доступные действия

- **Добавить услугу** — создание новой услуги с указанием названия, цены и продолжительности
- **Изменить услугу** — редактирование существующей услуги (название, цена, продолжительность)
- **Удалить услугу** — удаление услуги с подтверждением
- **Список услуг** — просмотр всех услуг с ценами и продолжительностью

### Структура услуги

| Поле              | Описание                                                   |
| ----------------- | ---------------------------------------------------------- |
| Ключ              | Уникальный идентификатор (латинские буквы и подчёркивания) |
| Название          | Отображаемое название услуги                               |
| Цена              | Стоимость в рублях (может быть пустой)                     |
| Продолжительность | Время в минутах (обязательно)                              |

### Отображение цен

Цены услуг показываются пользователям:

- В списке услуг (`/services`)
- При выборе услуги в сцене записи

### Файл хранения

Услуги хранятся в файле `services.json` в корне проекта. При первом запуске после обновления существующие услуги мигрируются из кода в этот файл автоматически.

### Валидация

- Ключ услуги должен быть уникальным
- Название не может быть пустым
- Цена должна быть числом >= 0 (опционально)
- Продолжительность должна быть числом > 0

## Напоминание для неактивных клиентов

Система автоматически отправляет напоминания клиентам, которые не посещали салон более 21 дня.

### Как это работает

- Проверка выполняется ежедневно в 11:00 по таймзоне салона
- Бот использует оптимизированный алгоритм (O(n) вместо O(n*m)) для быстрой проверки клиентов
- Система проверяет поле `Последняя_запись_UTC` из таблицы клиентов как основной источник данных
- Бот анализирует всех клиентов и находит тех, у кого:
  - Поле `Последняя_запись_UTC` указывает на дату более 21 дня назад
  - Нет активных (неотменённых) записей (быстрая проверка через Set)
  - Есть telegramId для отправки сообщения
  - Клиент не забанен
  - Напоминание ещё не отправлялось (поле `Напоминание_21день_UTC` пустое)
- **Автоматическое обновление:** Поле `Последняя_запись_UTC` автоматически обновляется при завершении записи (статус "исполнено")

### Что отправляется клиенту

- Дружелюбное сообщение с напоминанием о том, что прошло время с последней стрижки
- Призыв записаться на новую стрижку
- Напоминание отправляется только один раз

### Сброс напоминания при новой записи

Когда клиент записывается на новую услугу, поле `Напоминание_21день_UTC` автоматически очищается. Это позволяет клиенту снова получить напоминание через 21 день после новой записи.

### Поля в таблице

В листе `Клиенты` используются следующие колонки:

- `Последняя_запись_UTC` — дата и время последней завершённой записи (ISO UTC). Автоматически обновляется при завершении записи. Используется системой напоминаний как основной источник данных.
- `Напоминание_21день_UTC` — дата и время отправки напоминания (ISO UTC). Пустое значение означает, что напоминание ещё не отправлялось.

### Отчёт менеджеру

После выполнения проверки бот отправляет менеджеру отчёт:

- Список клиентов, получивших напоминание
- Количество успешных отправок
- Количество ошибок (например, если клиент заблокировал бота)
